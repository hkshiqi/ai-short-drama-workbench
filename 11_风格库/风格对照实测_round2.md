## 三、本次暴露的 2 个新问题

### 问题 1 · 强风格会覆盖人物身份（`ROMANCE_SOFT`）

**现象**：
- 角色从"28 岁饱经风霜的外卖员"变成"20 岁偶像剧男主"
- 皮肤从粗糙有质地 → 通透发光
- **疤痕消失、眼袋消失、法令纹消失**

**病因**：`ROMANCE_SOFT` 的提示词含"皮肤通透明亮""高调明亮布光""梦幻唯美"，这些词优先级高于"高细节皮肤纹理"和锁定词里的"肤色偏黄白"。

**影响**：**这是短剧的致命问题**——同一个角色在不同集换了风格，观众会认为"换演员了"。

**修法（写进规范）**：
```
① 人物特征词必须在风格词之后再回声一次（不只是标志物，还有年龄/肤质/眼袋）
   示例追加：「保持 28 岁男性肤质，保留眼袋与法令纹，皮肤有真实纹理不磨皮」
② 柔光类风格的 negative 必须加：「磨皮, 无瑕疵, 年轻化, 美颜, 皮肤发光」
   目前 ROMANCE_SOFT 的 negative 只有「硬光, 冷调, 粗颗粒, 脏」，缺"磨皮/年轻化"
③ 全剧只能用 1 个主风格 —— 这条已经是铁律，本次进一步验证了为什么
```

### 问题 2 · 场景锁定词会压制风格词（`ANCIENT_CN`）

**现象**：选了"古装国风（绢本质感、烛火窗棂、丝绸木质）"，但出图**完全没有古装特征**，仍是现代小巷 + 霓虹 + 夹克。

**病因**：场景锁定词 `SCN_ALLEY_NIGHT` 里写满了"米白瓷砖墙、生锈空调外机、积水、品红霓虹招牌"，这些都是**强烈的现代场景锚点**，权重压过了古装风格词。**模型选择了"现代巷子"，丢弃了"古装质感"。**

**这是个重要的架构认知**：
```
风格词 vs 场景词 冲突时 → 场景词赢
因为场景词描述"这是什么地方"（物理事实），风格词描述"看起来像什么"（渲染方式）
```

**修法**：
```
① 风格必须与场景年代/类型匹配（已在速查表里，但没做成硬门禁）
   古装剧 → 场景必须是古装场景（木楼/青石板/油灯），不能是城中村
② 增加匹配性硬门禁：style.group 与 scene.era 必须兼容
   古装类风格（ANCIENT_CN/INK_WASH/FANTASY_EPIC）只允许配古装场景
③ 也就是说：这不是"风格不生效"，而是"我拿错了测试素材"
   —— 用一个现代夜雨巷去测古装风格，本来就不可能对
```

## 五、招牌文字问题（Round 1 的遗留）已部分改善

Round 1 四张图的招牌文字**全部乱码**。
Round 2：
- `CINEMA_REAL`：招牌出「**龍城**」✅ 真实可读
- `RETRO_HK`：招牌出「**大發冰室**」✅ 港式正确
- `RETRO_90S_CN`：招牌出模糊但像样的字 ✅ 有年代感
- `DOUYIN_HIGH` / `CYBERPUNK` / `SUSPENSE_DARK`：仍乱码 ❌

**推测原因**：Round 2 负向词里加了「招牌文字乱码」，但只对部分风格有效（渲染管线不同）。

**结论**：文字仍不可靠，**规范里"文字类元素出图后合成"这一条必须执行**，不能指望模型。
