# 15 秒抽卡制生产规范（BLOCK-GACHA v1）

> 核心命题：**把"整片生成"降维成"15 秒块 × 有限抽卡 × 尾帧继承拼接"。**
> 15 秒块是全流程唯一的生产单元、计费单元、验收单元、返修单元。配音、表情、BGM、音效、字幕全部挂在块上，一块一交付。

---

## 一、为什么是 15 秒（三条硬理由，不是拍的）

| 理由 | 计算 |
|---|---|
| **音乐整拍** | 统一 **128 BPM** → 1 拍 = 0.46875s，1 小节(4/4) = **1.875s**，**8 小节 = 15.000s 整** |
| **平台节奏** | 短剧观众注意力单元 ≈ 15s；每 15s 必须有一次情绪推进或信息增量，否则划走 |
| **抽卡成本** | 15s = 4–6 镜；重抽一块 ≤ 6 次生成，可承受。整集 90s 重抽 = 灾难 |

**推论（全流程锁死）**
- 一集 90s = **6 块**（B01–B06）；120s = 8 块；60s = 4 块
- 12 集 = 72 块
- **单镜时长必须吸附节拍网格**：`1.875s`（1 小节）或 `3.75s`（2 小节）
- 8 小节内的合法组合：`3.75×4` / `1.875×8` / `3.75+1.875×5+...`（任意和 = 15.0s）

> 这一条把"AI 生成的随机时长"和"剪辑卡点"焊死了。**不再存在"这镜 4.3 秒怎么办"的问题。**

---

## 二、块切分规则（把剧本切成 15s）

在 S1 剧本阶段就切块，标进 `script.json` 的 `block` 字段。

| 规则 | 说明 |
|---|---|
| **一块一情绪** | 每块只有一个情绪基调和一次微推进（铺垫→加压→反转的小格） |
| **一块不换景** | 换景 = 换块。一块内最多 1 个场景 |
| **一块一钩** | 每块结尾有软钩（不是硬钩，硬钩只在集末） |
| **块界落在节拍线上** | 15s 整，不许 14.2 / 16.8 |
| **块末镜尾帧 = 下块首镜参考** | 见第五节，这是连贯性的全部秘密 |
| **产品镜头不跨块** | L2/L3 必须在同一块内起止，避免跨块一致性风险 |

### 集末硬钩的量化位置
```
块 5 内核（75–90s）：反派得意 → 主角一句话 → 断在"话说完但没解释"的那一帧
块 6 不是用来收的，是用来"断"的
```
→ 若一集 6 块，**第 6 块专门做钩子**，不作叙事收尾。

## 四、一次成型块工作流（PIPELINE ONE-BLOCK）

> 你说的"一次性生成"——**在工具层不存在一个按钮能出画面+表情+配音+BGM**；
> **在流程层可以做到"一块一交付、一次跑完"。** 下面是这个流水线。

```
                    ┌─────────── 同一块内并行 ───────────┐
[B01 块卡] ──┬──▶ ① 音频先行：TTS 对白 + BGM 8小节 + 音效  → block_audio.wav（含 ducking）
             │
             └──▶ ② 画面：首帧抽卡 → 视频抽卡 → 尾帧继承链
                                  │
                                  ▼
             ③ 时长对齐：画面总长吸附 15.0s（用 1.875 网格修正）
                                  │
                                  ▼
             ④ 合成：concat → 混音 → 烧字幕 → B01.mp4（15.000s）
                                  │
                                  ▼
             ⑤ 块级验收（12 项）→ 入池 / 返修（只重跑该块）
```

### 关键顺序：**音频先行（voice-first）**
先出配音，才能定镜长。台词 3.2s → 该镜必须落在 3.75s（2 小节），多出的 0.55s 做留白/呼吸。
反过来先做画面会全程返工。

```
TTS 出 wav → ffprobe 量时长 → 向上取整到节拍网格 → 写进块卡的 dur_bar → 再生成画面
```

### 块内并行度
| 步 | 能否并行 | 说明 |
|---|---|---|
| ① 音频 | ✅ 与 ② 完全并行 | 音频不需等画面 |
| ② 首帧抽卡 | ✅ 块内 4–6 镜可同时抽 | 互相独立 |
| ② 视频抽卡 | ❌ **串行** | 必须尾帧继承，第 N 镜要等第 N-1 镜尾帧 |
| ③④⑤ | ❌ 串行 | 依赖 ②完成 |

> **这是整个方案最大的时间成本点：视频抽卡必须串行。**
> 优化手段：先并行抽 2 版首帧，选定后再串行跑视频；串行时块 N+1 的首帧抽卡已经可以并行开跑（跨块并行，块内串行）。

## 五、连贯性的唯一实现方式：尾帧继承链

**这是"匹配成连贯短视频"的技术答案。**

```
块 B01                        │  块 B02
SH01 ─尾帧─▶ SH02 ─尾帧─▶ SH03 ─尾帧─▶ SH04 ─尾帧─╮
                                                    │（块界继承）
                                                    ▼
                                      SH05首帧参考 ← B01_SH04_tail.png
```

### 操作步骤（每镜照做）
1. 生成 SH0N 视频后 → `ffmpeg -sseof -0.1 -i SH0N.mp4 -frames:v 1 SH0N_tail.png` 导出尾帧
2. **人工/自动过一遍尾帧**：脸崩了吗？衣服对吗？光线对吗？→ 不过就重抽本镜，不许带着崩帧往下传
3. SH0(N+1) 的 `first_frame_prompt` 用**图生图/首帧参考**：`SH0N_tail.png` + 文字提示词
4. 首帧里"延续上一镜的"信息用文字显式写清：`他保持上一镜的姿势，肩膀仍未放下`
5. 块界同理：B01 末镜尾帧作为 B02 首镜参考

### 什么时候必须断链（重开首帧，不用尾帧继承）
| 情况 | 原因 |
|---|---|
| 换场景 | 环境全变，继承会带脏背景 |
| 换装 | 服装不一致直接穿帮 |
| 时间跳跃（夜→晨） | 光线冲突 |
| 上一镜尾帧已崩（脸/手） | 崩帧会传染整块 |
| 景别从 ECU 跳到 FS | 参考图信息量差太大，继承反而干扰 |

> **一集里连续继承链长度上限 = 4 镜。** 超过 4 镜必漂。到 4 镜就主动断链重开（用角色定妆图 LOCK 图作参考）。

## 六、抽卡制（GACHA）：数量、评分、复现

### 6.1 抽卡配额

| 层级 | 抽数 | 说明 |
|---|---|---|
| 首帧（图） | **4 张** | 便宜，多抽。选 1 |
| 视频（每镜） | **3 条** | 贵，控量。选 1 |
| 视频（关键镜：集末钩、打脸、产品 L3） | **6 条** | 这 3 类镜决定成败，舍得抽 |
| 整块重抽 | ≤ 2 次 | 超 2 次说明块卡写错了，回改块卡不要硬抽 |

**单块成本上限（12 镜集均摊）**：首帧 4×5=20 张图 / 视频 3×5=15 条视频。
一集 6 块 → 120 图 + 90 视频。抽卡预算按这个下。

### 6.2 抽卡评分表（每张候选都要打分，不许"感觉这个好"）

| # | 维度 | 判据 | 权重 |
|---|---|---|---|
| 1 | **人物一致** | 对照 `LOCK_V1` 逐项核：脸型/眼/眉/发型/疤/标志物。少一项扣分 | 30% |
| 2 | **表情到位** | 对照 `expr_code` 的肌肉级描述，强度是否对 | 20% |
| 3 | **动作合理** | 符合 `video_prompt`，无多手/融合/穿模 | 15% |
| 4 | **构图与景别** | 景别对不对，人物在安全区内，产品位对 | 15% |
| 5 | **画质** | 无糊、无噪、无塑料感、无文字水印 | 10% |
| 6 | **接续性** | 与上一镜尾帧的光线/服装/姿态能接上 | 10% |

**及格线 7.0 / 10。低于 7.0 直接弃，不允许"凑合用"** —— 一条凑合镜会毁掉整块观感。

## 七、块级验收（12 项，全绿才入池）

| # | 检查 | 判定方式 |
|---|---|---|
| 1 | 总时长 = 15.000s ±0.05s | `ffprobe` |
| 2 | 每镜时长 ∈ {1.875, 3.75}s | 读块卡 |
| 3 | 块内切点全落在小节线上 | 时间线比对 |
| 4 | 人物跨镜一致 | 抽帧比对 LOCK 清单 |
| 5 | 表情码与强度落地 | 抽帧比对表情表 |
| 6 | 口型三对齐（音/嘴/字幕偏 <0.15s） | 抽帧 + 波形 |
| 7 | BGM 三层齐全，无爆音 | 频谱 |
| 8 | 对白清晰（BGM ducking 生效） | 听感 + 电平 |
| 9 | 字幕无错字、不出安全区 | 逐屏看 |
| 10 | 产品镜头与点位表一致（如含） | 比对 CSV |
| 11 | 无禁用词、无疗效承诺 | 文本扫描 |
| 12 | 尾帧可用于下一镜继承（无崩帧外传） | 看尾帧图 |

## 八、拼接（Block → Episode）

```
B01.mp4 + B02.mp4 + ... + B06.mp4
  ├─ 视频：直接 concat（全部已统一 1080×1920/30fps/yuv420p/H.264）
  ├─ 音频：块间加 0.0s 空隙（不做过场留白，短剧要快）
  ├─ 块界处理：硬切 + 1 个 whoosh（0.15s）盖住块缝
  └─ 集末：悬念卡 1.5s + 关注引导
```

**块界绝不做转场特效**（AI 素材做转场必崩）。
块界靠三样东西缝合：`硬切` + `whoosh 音效` + `BGM 不中断`（BGM 跨块连续，贯穿整集，块界只换镜头不换音乐）。

> **BGM 跨块连续** 是让 6 个块听起来是"一集"而不是"6 段"的关键。BGM 按整集 90s 做（48 小节 @128BPM），块只是它的切片。
